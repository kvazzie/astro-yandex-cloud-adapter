# Local S3 upload and update tests

Run these checks with [Nix and devenv 2 or later](https://devenv.sh/getting-started/):

```sh
devenv shell -- pnpm install --frozen-lockfile
devenv test
```

The repository's `devenv.lock` pins SeaweedFS 4.46. `devenv test` starts its native
`weed mini` process, builds the adapter, and runs `tests/integration/s3.test.ts`.
Vitest waits up to 30 seconds for an authenticated `HeadBucket` on `issue11-ready`.
The process binds to loopback and uses fixed local test credentials. No Docker or
cloud credentials are needed.

Each test builds an isolated application for `/` or `/docs`. The upload helper in
[`tests/integration/helpers/client-artifact.ts`](../tests/integration/helpers/client-artifact.ts) parses the
generated Deployment Manifest, reads its Client Artifact directory, and uses the
declared route object keys. It places the remaining public files and browser
assets under the manifest's base prefix. Each `PutObject` includes a MIME type
looked up by extension, with a UTF-8 charset for text types and
`application/octet-stream` for unknown extensions.

The suite checks the complete object listing, generated bytes, and `Content-Type`
through `GetObject` and `HeadObject`. It includes HTML pages, JSON and XML
endpoints, public text and binary files, and generated SVG, JavaScript, and CSS
assets. The update rebuilds changed HTML, public files, and browser assets, then
uploads them to the same bucket. Objects owned by another application, both
inside and outside `/docs/`, retain their bytes, MIME types, and custom metadata.
Repeating the upload produces the same object listing and readback.

The upload procedure only adds or overwrites artifact keys. It leaves old hashed
assets and unrelated keys in place. It does not infer deletion or cache policy.
Deployment and Provisioning remain outside the Bare Adapter; all upload code and
S3 dependencies live in test tooling.

The test file declares the expected page keys, base placement, MIME types, and
update behavior. Reusable S3 assertions live in
[`tests/integration/lib/s3.ts`](../tests/integration/lib/s3.ts), with callers supplying
the expected keys, bytes, and metadata. Fixture setup and builds contain no assertions.
Devenv's Node scripts call `scripts/local-s3.mjs` for the service and
`scripts/test-s3.mjs` for test orchestration and logging.

## Repeatability and results

Run `devenv test` again to repeat the checks. Every invocation uses a new temporary
SeaweedFS data directory and unique test buckets. Tests delete exact file keys and
then their own buckets. SeaweedFS can leave empty directories after object deletion,
so deletion of test-owned buckets uses its recursive bucket cleanup. The process
wrapper stops SeaweedFS before removing its data directory, including on test
failure or interruption.

The service uses HTTP ports 18333, 18888, 19333, 19340, and 23646, plus their gRPC
ports at HTTP port + 10000. For concurrent runs in separate worktrees, select a
different port offset:

```sh
S3_TEST_PORT_OFFSET=1000 devenv test
```

The offset must be between 0 and 20000. Choose an offset whose ports are free.
On readiness failure, the test reports the last S3 error and the service log.

`pnpm test`, `pnpm test:unit`, and `pnpm test:integration` run without an S3 service.
To use an already running local S3 service, create a readiness bucket and run:

```sh
S3_TEST_ENDPOINT=http://127.0.0.1:8333 \
S3_TEST_READY_BUCKET=issue11-ready \
S3_TEST_ACCESS_KEY=issue11-local \
S3_TEST_SECRET_KEY=issue11-local-secret \
pnpm test:s3
```

The endpoint must use HTTP on loopback. The test credentials need permission to
create and delete test buckets and read, list, write, and delete their objects.
`pnpm test:s3` fails if the endpoint is missing or unavailable.

The CI job **Local S3 uploads and updates** runs the same `devenv test` command.
Its `local-s3-results` artifact retains these files for release review, including
failed runs:

- `.artifacts/local-s3.log`, with Node.js, pnpm, and SeaweedFS versions and Vitest results.
- `.artifacts/local-s3.xml`, the JUnit test report.
- `.devenv/s3.log`, the service startup and shutdown log.

These tests cover local S3 object behavior. They do not establish Yandex Object
Storage website index, error, redirect, or other cloud-specific behavior. Real
Yandex Cloud verification remains a separate [stable release gate in issue #83](https://github.com/kvazzie/astro-yandex-cloud-adapter/issues/83).
