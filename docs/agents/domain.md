# Domain Docs

Before exploring, read `GLOSSARY.md` at the repo root and the relevant ADRs in `docs/adr/`.

Use the glossary vocabulary from `GLOSSARY.md` in issue titles, proposals, hypotheses, and tests. If a needed concept is missing, note it for domain modeling.

If output contradicts an existing ADR, flag the conflict explicitly instead of silently overriding it.

## File structure

This is a single-context repository:

- `GLOSSARY.md` contains the domain glossary and boundaries.
- `docs/adr/` contains repository-wide architectural decisions.
