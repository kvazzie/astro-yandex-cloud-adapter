# Discover runtime dependencies with @vercel/nft

Function Artifact preparation discovers the runtime packages and files that the emitted server loads with `@vercel/nft`, the Node file tracer that Astro's Vercel and Netlify adapters use, instead of maintaining its own loader analysis. The adapter keeps exact version selection, npm graph semantics and lockfile generation; the tracer only names what the emitted code imports. We accept the tracer's limits deliberately: a load that static tracing cannot follow is not discovered and is not rejected at build time, so the deployed function fails at runtime with "Cannot find module". The `includeDependencies` option of `dependencyStrategy: "install"` pins such packages explicitly, matching the role of `includeFiles` in the Vercel adapter.

Known undiscovered loads include `process.getBuiltinModule("module").createRequire(…)`, an inline `createRequire(import.meta.url)("pkg")` call, `import()` or `require()` with a computed specifier, files reached only through `require.resolve` or `import.meta.resolve`, and loaders selected at runtime between modules or values. Reports of these patterns are expected behavior: the fix is `includeDependencies`, a fixed `import`, or bundling the package, not a broader analysis in this adapter.
