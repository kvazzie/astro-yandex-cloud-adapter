# Version the deployment manifest contract

Implementation status: The revised draft Manifest contract is tracked in #7 and implemented later in the release stack. This historical layer still emits the original draft v1 schema, including its legacy build metadata and Client Artifact inventory. Target Modifier provenance is part of the revised contract, and Gateway template generation is planned under #67. A Serving Artifact's service follows its artifact kind; this decision does not require a separate per-artifact Target field.

The Deployment Manifest is a deployment-product-neutral contract for humans and tools that consume Yandex Cloud builds. It records the selected Target and Target Modifiers as provenance, plus the Serving Artifacts actually produced and their routing and runtime requirements; it does not allocate resources or prescribe cache policy, domains, or SST links. Consumers decide how to satisfy those requirements, while an API Gateway Modifier may also generate a customizable OpenAPI template from the same route map. Before the first npm publication, the draft schema version 1 may change; after publication, each version has a published JSON Schema, additive changes may retain the version, and a breaking field or invariant change requires a new schema version.
